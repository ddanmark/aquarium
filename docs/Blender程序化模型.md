# 用 Blender 程序化生成写实模型（替代 hy-3d 额度）

结论先说：**可以，但只能到「半写实」这一档**。

Blender 5.3 能在本机 headless 跑脚本，把几何、UV、贴图、法线全部程序化生成，导出的 GLB 能原样走项目现有的
`ingest.py` 链路（pack → rig 12 骨 → Turn → check_skin 闸门），**完全不消耗 hy-3d 额度**。
但它**替代不了** AI 生成的照片级质感：没有真实鳞片几何、没有半透明鳍、没有湿润高光与次表面散射，
有机不规则形态也不如 AI 自然。它的定位是：**低模品种的明显升级 + AI 断供时的填充方案**。

已落地样板：`tools/blender/guppy_tuxedo.py`（孔雀鱼 · 红礼服）。

## 二、模型必须满足的硬约束

这些不是风格偏好，是**现有链路的硬性要求**，违反任何一条都会失败或错位：

| 约束 | 来源 | 具体要求 |
| --- | --- | --- |
| 单 primitive | `rig_fish.py` 只读 `meshes[0].primitives[0]` | 身体、鳍、眼必须合并成**一个 mesh、一个材质、一张贴图**。多材质会拆成多 primitive，只有第 0 个会被绑骨 |
| 体长主轴沿 X | `head_is_plus_x()` 按 X 分箱判断头尾 | 头朝 +X 或 -X 都行，脚本会自动摆正 |
| Z-up 导出 | `rig_fish.py` 先 `pop("rotation")` 再手工烘焙 `(x,y,z)→(x,-z,y)` | 必须 `export_yup=False`。若导出成 Y-up，鱼会侧躺 |
| 顶点 > 500 | `ingest.py` 直接拒绝过小模型 | 本样板 3011 顶点 |
| 无退化面 | `check_skin.py` 按形变判「塌缩/爆炸」 | 尾鳍根部不能收成一个点，用 0.055 的弧半径起步 |
| 材质要有 `normalTexture` | `pack_model.py` 原来硬编码假设 | 已加兜底；但仍建议做法线贴图，质感更好 |

## 三、样板脚本的结构

`tools/blender/guppy_tuxedo.py`，约 600 行，全部用 `bpy` + `numpy`，不依赖外部库。

```
参数表      T_H / T_W   沿体长的体高、体厚剖面（改这里就能换体型）
脊椎线      spine_z()   背部略拱、腹部略平，避免对称椭圆
几何        build_body()   沿 X 放样椭圆截面，两端封口成闭合体积
            build_tail()   XZ 平面大扇面，扇缘波浪 + 沿 Y 褶皱，根部插进尾柄 0.18
            build_dorsal() 背鳍，沿背包线向后再向后倾
            build_anal()   臀鳍，腹侧向后下
            build_pectoral() 胸鳍，体侧小扇，绕 X 轴下压
            build_eye()    眼球，球心嵌在头侧肌肉里，只露出一小段
UV          手工写入     身体 u=体长 v=周向；鳍按局部参数映射到各自条带
贴图        make_texture()        1024² sRGB：红礼服渐变 + 鳞片网纹 + 侧线 + 鳃盖线 + 尾鳍斑点
            make_normal_texture() 1024² Non-Color：鳞片网格 + 鳍条细纹的高度场求梯度
材质        单一 Principled BSDF：baseColor + normalMap，粗糙度 0.36，IOR 1.38
导出        export_yup=False / 单对象 / 不带动画
渲染        Cycles CPU 三点光 + Standard 色彩变换（AgX 会把饱和红压成粉白，没法判断配色）
```

贴图纵向分条带，互不重叠，避免采样串色：

| 条带 | v 范围 | 内容 |
| --- | --- | --- |
| 身体 | 0.000–0.560 | 银蓝 → 深红 → 近黑的红礼服渐变，带鳞片网纹、侧线、鳃盖后缘暗线 |
| 尾鳍 | 0.575–0.790 | 红底黑缘 + 放射细纹 + 斑点 |
| 背鳍 / 臀鳍 | 0.800–0.845 | 红到近黑的竖向渐变 |
| 胸鳍 | 0.855–0.885 | 浅粉红到暗粉 |
| 眼睛 | 0.895–0.990 | 黑底 + 金环 + 黑瞳 + 白高光（等距柱面展开） |

## 四、为接入而改的三处通用脚本

都是**默认行为零变化**的增量改动：

1. **`tools/rig_fish.py`**：新增第 4 个可选参数「尾鳍起点 u」，默认 `0.93`（原硬编码值）。
   原逻辑用 `u > 0.93` 判尾鳍顶点、`x_head - 0.965*span` 定尾鳍骨位置，隐含假设「尾鳍很短」。
   孔雀鱼尾鳍占全长 36%，用旧值只认出 **46 个**尾鳍顶点、尾鳍骨还被放到扇面最外缘（尾巴会甩飞）。
   改成可配后认出 **587 个**，骨位置也落到扇面根部。`TAIL_BONE_U = (TAIL_U+1)/2`，默认仍是 0.965。
2. **`tools/ingest.py`**：新增 `--tail-u=<值>`，透传给 `rig_fish.py`；不传则行为完全不变。
3. **`tools/pack_model.py`**：原本硬编码「0 号图是法线、1 号是基础色」，遇到没有 `normalTexture` 的材质直接
   `KeyError`。改为缺失时把基础色指向 0 号图，有法线贴图时逻辑一字未动。

## 六、能力边界（重要）

**能做到：**

- 形体、比例、朝向完全可控，能按真实物种论文级的比例调（体高/体长、尾鳍占比、鳍位）
- 配色渐变、鳞片网纹、鳍条纹理、鳃盖线、眼睛高光，全部程序化、可复现
- 换一组剖面参数就是一族的另一条鱼；换配色表就是同种鱼的另一个色型 → **天然支持批量出变体**
- 零额度、零网络、确定性输出，任何一次重跑结果完全一致

**做不到：**

- 照片级真实感：没有真实鳞片几何、没有半透明鳍膜、没有湿润高光与次表面散射
- 单材质限制导致鳍无法独立半透明（整条鱼只能共用一套材质参数），只能靠贴图模拟
- 有机不规则形态（褶皱、破损、粘连）不如 AI 自然
- 解剖细节需要逐条手调参数，不是一句话就能出图

**按项目现状的建议**：写实鱼继续等额度用 AI；**水草、石头这类形态简单且不动的物件最适合 Blender 路线**；
鱼可以用 Blender 版作为低模品种的升级，或作为 AI 断供期的过渡资产。

## 八、扩展下一个品种怎么改

1. 复制 `guppy_tuxedo.py`，改 `T_H` / `T_W` 剖面表 → 换体型（纺锤、侧扁、细长）
2. 改 `build_tail()` 的 `Lf` / `PHI` / 边缘波浪 → 换尾型（扇尾、剑尾、圆尾）
3. 改 `make_texture()` 里的颜色常量与渐变折点 → 换色型
4. 若新鱼尾鳍占比与 AI 模型差异大，用 `--tail-u=` 调尾鳍起点（经验值：`1 - 尾鳍长/全长 - 0.02`）
5. 跑 `verify_assets.js` 确认零法线与资源一致性

## 九、A 档落地：clearcoat 湿润 + transmission 透鳍（已接入）

目标：在不改 `rig_fish.py` 绑骨链路、不加多 primitive 的前提下，把「湿润高光」和「半透明鳍膜」做出来。

### 9.1 先探测导出器能力，别赌

用一个最小场景（球体 + 各输入接 Image Texture）实测 Blender 5.3 的 glTF 导出：

| 目标 | 导出器 | 处理方式 |
| --- | --- | --- |
| `KHR_materials_clearcoat` + `clearcoatTexture` | ✅ 直接导出 | 靠导出器 |
| `KHR_materials_transmission` + `transmissionTexture` | ✅ 直接导出 | 靠导出器 |
| `KHR_materials_ior` | ✅ 直接导出 | 靠导出器 |
| `metallicRoughnessTexture`（Roughness 接贴图时） | ✅ 直接导出 | 靠导出器 |
| `KHR_materials_volume` / `iridescence` / `occlusionTexture` | ❌ 不导出 | 留给下一档，需手工注入 JSON |

探测脚本：`tools/blender/_probe_ext.py`。

**推论**：单材质 + 逐像素遮罩就能做「鳍透光、身体不透」，**不需要多材质，也不需要改 `rig_fish.py`**。之前说「单材质限制下鳍无法独立半透明」是错的——`transmissionTexture` 和 `thicknessTexture` 都是逐像素的。

### 9.2 三张控制贴图（512，Non-Color）

`make_control_textures()` 按 UV 条带分区，全部线性数据：

| 贴图 | 通道 | 内容 |
| --- | --- | --- |
| `_tr.png` | R=G=B=透光率 | 尾鳍 0.38 / 背鳍 0.34 / 胸鳍 0.30 / 体表 0.04 / 眼 0 |
| `_cc.png` | R=G=B=清漆强度 | 体表 0.20 / 鳍 0.10 / 眼 0.85 |
| `_mr.png` | R=0、G=粗糙度、B=金属度 | 体表 0.34（叠鳞片起伏 ±0.05）/ 鳍 0.15 / 眼 0.05，metallic 恒 0 |

### 9.3 关键坑：未用通道填 1 会把标量输入拉满

第一版渲染出来整条鱼像玻璃，红色全被洗掉。排查过程：贴图本身正确（银蓝→深红→近黑），UV 也正确（吻端 u=0.027 → 尾柄 u≈1）。

**根因**：`_save_linear` 里 `px` 初始化为全 1，只写了 R 通道。Blender 把颜色输出接到**标量输入**（Transmission Weight / Coat Weight）时取的是**亮度** `0.2126R + 0.7152G + 0.0722B`。于是：

- 尾鳍 R=0.52、G=B=1 → 亮度 **0.90**
- 体表 R=0.04、G=B=1 → 亮度 **0.79**

**整条鱼实际是在 0.79–0.90 的透光率下渲染的**，等于一块玻璃。修法是让 R=G=B 相等（`_save_linear(..., gray=True)`），亮度才等于目标值。

同类陷阱：任何「单通道贴图接标量输入」的场合都要走这一步，否则未用通道的默认值会整体抬高标准。

### 9.4 参数为什么不能开大

- **transmission 0.86 → 0.38**：Cycles / Three.js 的 transmission 是光直接穿过、不带吸收色，开太大鳍会变成「灰青薄纱」，背景色把红色冲掉。0.38 左右才有「半透 + 自带色素」的鱼鳍感。
- **clearcoat 0.55 → 0.20**：0.55 会出一层镜面把基础色全盖住，鱼变银白。鱼体表不是瓷器，0.2 足够出湿润感。
- **Coat Roughness 0.09 → 0.16**：太低会让高光收成一个点，太硬。

### 9.5 `tools/pack_model.py` 的改造（零回归）

旧实现按「0 号法线 / 1 号基础色 / 2 号丢弃」猜索引。多出三张遮罩贴图后必然错位删图。改成：

1. **按材质扩展自动分类**：带 `KHR_materials_transmission/clearcoat/volume` → 程序化 PBR，保留 `metallicRoughnessTexture` 与原参数；否则 → AI 产物，沿用旧行为（丢弃常为纯红的 mr 贴图、统一 `roughnessFactor`）。
2. **按槽位语义压缩**：遍历材质里所有 `*Texture` 槽，`baseColorTexture` / `emissiveTexture` 用 JPEG 92，法线与各类遮罩用 PNG 无损（JPEG 的 8×8 块会让法线出方格、遮罩边缘出毛刺）。
3. **按引用关系重建 image / texture 索引**，不再硬编码序号。

**回归验证**：`betta_ai.glb` 39.37 → 2.24 MB，仍只保留法线 + 基础色两张图、mr 贴图仍被丢弃、`roughnessFactor 0.5` 不变。

### 9.7 A 档没做的（留给下一档）

- `KHR_materials_volume`（`thicknessTexture` + `attenuationColor`）：把「鳍薄体厚」和「透光带红色」做实，需手工注入 JSON。现在的透光不带吸收色，是鳍偏灰的直接原因。

## 十、v2：针对「太假」的几何与贴图升级

用户反馈：`孔雀鱼·红礼服的鱼的3D形象太假了，没有暹罗斗鱼那种像鱼的样子`。

### 10.1 先量化差距，别猜

| | 参数化低模（原） | 程序化 v1 | **程序化 v2** | 暹罗斗鱼（AI） |
| --- | --- | --- | --- | --- |
| 顶点 | 473 | 3,007 | **10,964** | 28,174 |
| 三角面 | 786 | 5,516 | **21,056** | 45,000 |
| 贴图 | 1 | 5 | 5 | **2** |
| 材质扩展 | 无 | clearcoat/transmission/ior | 同左 | 只有 specular |

**关键发现**：斗鱼贴图更少、材质扩展更弱，反而「像鱼」。说明差距**不在材质**，主要在**几何密度 + 贴图的有机细节**。上一轮把力气花在材质上是打偏了。

### 10.2 三项改动

**① 几何密度（4 倍）**

| 部位 | 原 | 现 |
| --- | --- | --- |
| 体长段数 NT | 56 | 128 |
| 周向段数 NU | 30 | 60 |
| 尾鳍 NR×NA | 16×34 | 26×54 |
| 背鳍 / 臀鳍 | 12×10 / 10×9 | 22×16 / 18×14 |
| 胸鳍 / 眼 | 7×9 / 8×12 | 12×16 / 12×18 |

**② 体型起伏**：加**鳃盖鼓包**（`body_w` 在 t≈0.135 处乘 1.11 的高斯鼓包，这是「像鱼」最容易被忽略的轮廓）、背弓 0.045→0.055、腹部从 0.94 改 0.97（原来太扁像纸片）。

**③ 鳍的软组织感**：
- 多层褶皱：低频大波 `sin(5φ)` + 中频 `sin(13φ)` + 高频 `sin(29φ)`，原来只有两个频率，边缘规整得一眼看出程序生成
- 鳍尖后卷 `sweep = 0.10·R²·(1-0.5cos φ)`，模拟水阻
- 鳍条间膜起伏：`sin(φ·26)` 调制，让鳍不是一块平板

**④ 贴图有机化**：
- 鳞片从 `sin(u)·sin(vt)` 正交网纹改成**砖砌式错位排列**（真实鱼鳞是交错覆盖）+ 圆顶高度场 + 每片独立伪随机亮度
- 加**鳃盖青绿结构色**（孔雀鱼鳃盖有很强的金属反光）
- 加**体侧零散深斑**
- 红黑交界加 `jitter_u` 噪声，边界参差而不是平滑渐变
- 加低频色斑 `mottle`，打破线性渐变的机械感
- 吻端银白 `#cdd9dc → #9db4b2`（原来太白，头部渲成一块白）+ 头顶压暗

### 10.3 调参踩的坑：鳞片高光过强

第一版加完鳞片后，每个鳞片顶着一个白高光，像**塑料泡壳**，把红色全盖住。三处一起收：

- 鳞片基础色对比 `0.13 → 0.055`
- 法线高度 `0.22+0.62·dome → 0.34+0.32·dome`，`NormalMap Strength 1.10 → 0.60`
- clearcoat 体表 `0.20 → 0.14`、鳍 `0.10 → 0.07`
- 鳍粗糙度 `0.15 → 0.30`（0.15 太光滑，鳍条出金属白条）

| 骨骼 / 闸门 | 12 骨；Swim 1.53、Turn 1.15 均通过 |
| 内嵌包 | 39 模型 / 84.2 MB base64 |
| Three.js 实机 | 鳞片错落、半透明鳍、圆润轮廓均已可见 |

对照图：`models/_test/guppy_v2_vs_betta.png`（三代同管线对比）。

### 10.5 诚实的结论：程序化路线的上限在这里

改进后从「明显假」变成「能认出是红礼服的 CG 鱼」，但**仍达不到 AI 生成的生物感**。根源不是面数（已提到 2.1 万，斗鱼 4.5 万也不算多），而是：

1. **贴图缺少有机细节**：斗鱼的鳍有蓝紫→白→红的丰富渐变、身体有不规则斑点和明暗层次；程序化贴图是数学函数的叠加，层次感天然单薄。
2. **表面缺少微观起伏**：真实鱼体有皮肤褶皱、黏液层的细微高低，程序化只到「鳞片」这一级。
3. **单层鳍面**：虽然是 DoubleSide + transmission，但没有真实软组织的厚度与飘动。

**要跨过这道坎，只有两条路**：

- **AI 生成鱼皮无缝贴图**（走图片生成通道，不占 hy-3d 3D 额度）→ 投影到现有 UV 上。这是性价比最高的，几何不用动，贴图直接换掉。
- **照片投影（Projection Paint）**：找高清侧视照片投到 UV。效果最真，但需要素材，且单角度只能覆盖一面。

继续堆几何（到 4.5 万面）或继续调材质参数，边际收益已经很低。

## 十一、v3：叠加 AI 皮纹（ImageGen）

用户选择：`AI 贴图试试`。

### 11.1 思路：AI 只给细节，配色仍归程序化

直接把 AI 图当 baseColor 是最省事但最容易翻车的做法——AI 图有自己的整体色调和明暗分布，会覆盖掉「前银蓝 → 后深红」的品种特征。

所以采用**明暗细节层**方案：

```
最终颜色 = 程序化渐变（控制配色分布）
         × AI 明暗起伏（只取鳞片凸起、鳞缝、色斑）
```

这样既有 AI 学来的有机细节，又保证配色分布仍然正确。

### 11.2 生成与选型

三张候选（`models/_raw/ai_skin/`，单张约 5–10 积分）：

| 候选 | 内容 | 结论 |
| --- | --- | --- |
| A | 横向渐变：左银蓝灰虹彩 → 右深红近黑，鳞片层叠清晰 | **选用** |
| B | 强虹彩鳞片，但排列过于规则，像屋顶瓦片 | 弃 |
| C | 红黑斑驳带散点，但鳞片糊掉、缺少渐变 | 弃 |

Prompt 要点：`extreme macro photograph of fish body skin`、`silvery iridescent blue-grey → deep crimson and near-black`、`dense overlapping cycloid scales`、`flat even studio lighting, no shadows`、`seamless tileable`、`skin only (no fish outline, no fins)`、1024×1024。

### 11.3 水印处理：裁切比修补干净

ImageGen 产出右下角有半透明「AI生成 WORKBUDDY」压印。第一版用上方同尺寸内容覆盖 + 羽化，**残留仍可见**（半透明压印会透过覆盖层显现）。

改用**裁切**：水印固定在右下角 `y ≥ 938`，直接裁掉底部 116px 再纵向拉回 1024。鳞片只变形 12%，肉眼几乎看不出，且无任何修补痕迹。

### 11.4 两个必须处理的坑

**① 整体被压暗（最隐蔽）**

第一版叠加后整条鱼比素模还暗。原因是 AI 图本身「左亮右暗」，而这个趋势与程序化的「前银蓝后深红」**方向完全重叠**，等于暗上加暗。

解法：**按列归一化** `detail = luma / luma.mean(axis=0)`，把横向明暗趋势除掉，只留局部对比。纵向趋势保留（影响小）。

**② 鳞片被纵向拉长**

AI 图纵向约 26 片鳞，身体条带只有 573 行（1024 的 56%），直接铺满只剩 14 片 → 鳞片变成扁宽状。

解法：按 26:30 的比例压缩采样范围，`span = n_rows × 26/30`，让两个方向的片数接近。

| 指标 | 值 |
| --- | --- |
| 顶点 / 三角面 | 10,964 / 21,056（与 v2 相同，只换贴图） |
| 接入件 | `models/guppy_red_rigged.glb` 1.01 MB |
| 内嵌包 | 39 模型 / 84.3 MB base64 |
| Three.js 实机 | 体表细密鳞片层叠、色斑层次、半透明鳍均正常 |
| 门禁 | `verify_assets.js` 八节全过 |

三步进展对比：`models/_test/guppy_v1_v2_v3.png`。

### 11.6 还差什么（到斗鱼的距离）

| 维度 | 现状 | 斗鱼 |
| --- | --- | --- |
| 次表面散射 | 无（只有 transmission） | AI 模型自带柔和体积感 |
| 鳍的厚度 | 单层面 + DoubleSide | 薄但有实体感 |
| 整体光影分布 | 程序化贴图是均匀的 | AI 从参考图学到「哪里该亮哪里该暗」 |
| 皮肤微观起伏 | 只到鳞片级 | 有褶皱、黏液层的细微高低 |

**继续提升的现实路径**：给 AI 皮纹图再叠一层「法线烘焙」（把 AI 图的明暗当高度场生成法线），成本低；或者直接接受现状——它已经比参数化低模好一个量级。

## 十二、v4：头部解剖结构（嘴 / 鳃 / 眼）

用户进一步澄清：`是说孔雀鱼·红礼服的嘴/腮/眼睛和其他写实的3D模型不像，区别很大`。

不是贴图问题，是**头部结构缺失**。把头部放大看，问题很直接：

| 部位 | 改进前 | 真实鱼应有 |
| --- | --- | --- |
| 嘴 | 吻端是被切平的圆柱面，一个扁平小圆盘 | 上下颌分开、中间有横向口裂、口端位偏下 |
| 鳃 | 几何上**完全没有盖板**，只有贴图一条几乎看不见的暗线 | 独立的盖板，后缘有明显边界和台阶 |
| 眼 | 金色球体凸在体表，瞳孔偏到一边 | 嵌在眼窝里，黑瞳 + 虹膜环 + 高光在正面 |

### 12.1 嘴：口裂 + 上下颌

两处配合才成：

1. **前端顶点内收**：`t < 0.06` 的环，按 `cz`（周向高度）做窄高斯（σ 0.17）内收 0.115，上下颌（`|cz|` 大）反而前伸 0.030 形成唇缘。
2. **封口中心后移 0.05**：前端封口是一块平盘，如果不动它，会把口裂凹陷整个顶回原位，侧面看吻端仍是平的。后移后形成向内的漏斗，读起来才是「口」。

两个踩过的坑：

- **口裂高斯中心写反**：`czo = cz - 0.18` 会把缝抬到吻端上方，看起来像鼻孔；应该是 `cz + 0.20`（峰值在 `cz = -0.20`，偏下）。
- **σ 太大**：第一版 σ 0.30，影响约 1/3 的周向，变成「正前方一个方坑」，不像嘴。收到 0.17 只影响约 8%，才是细缝。

### 12.2 鳃：盖板 + 后缘台阶

只有「收」不够——侧光下分界太弱，看不出是盖板。改成**先鼓后收**：

```python
plate = 0.038 * math.exp(-((t - 0.155) ** 2) / (2 * 0.020 ** 2))   # 盖板鼓起 3.8%
seam  = 1.0 - 0.115 * _sstep(0.158, 0.178, t)                      # 后缘急收 11.5%
return w * (1.0 + gill + plate) * seam
```

`body_h` 同步收 4.8%，形成立体的盖板边缘。

贴图侧同步：盖板下影线从 `u=0.118` 移到 **0.172**（和几何台阶对齐，否则贴图和模型各说各话），强度 0.24→0.38，另加**鳃孔暗斑**（`u≈0.184`、`vt≈0.52` 下半部），这是「鳃在这里」的唯一提示。

### 12.3 眼：眼窝 + UV 投影修正

1. **眼窝**：`t∈(0.045,0.150)` 且靠近眼位置的体侧顶点，按二维高斯径向内收最多 6%（乘以 `|cy|^1.1`，只作用于体侧），让眼球嵌进去而不是浮在表面。
2. **UV 改平面投影**：原来用等距柱面的 `u` 当横坐标，球的中线（`u=0.12`）被当成瞳孔，所以整颗眼渲成金色珠子、瞳孔偏到一边。改成按球面点相对眼中心的 `(dx, dz)` 做正面平面投影，瞳孔才落在朝外那一侧的正中。
3. 贴图瞳孔范围放大（`smoothstep(0.34,0.50)`）+ 虹膜收窄（`0.46→0.88`）。

| --- | --- |
| 顶点 / 三角面 | 10,964 / 21,056（结构改动没加密度） |
| 接入件 | `models/guppy_red_rigged.glb` 1.1 MB |
| 内嵌包 | 39 模型 / 84.3 MB base64 |

## 十三、v5：修上下颠倒 + 按参考模型调形态

用户反馈两点：`要参考已有的孔雀鱼的写实模型来调整`、`现在的孔雀鱼·红礼服是上下颠倒的`。

### 13.1 一个重要发现：项目里已有孔雀鱼写实模型

`models/guppy_rigged.glb` 是 **AI 生成的写实模型**（26,855 顶点 / 45,000 三角面，与暹罗斗鱼同规格），不是参数化低模。它就是「已有的孔雀鱼写实模型」，可以直接当形态基准。

### 13.2 上下颠倒：根因在烘焙，不在建模

三个模型的包围盒一对比就露馅：

| 模型 | y 范围 | 说明 |
| --- | --- | --- |
| `guppy_rigged`（AI） | 0 → +0.63 | 全非负，原点在腹部底 |
| `betta_rigged`（AI） | 0 → +0.84 | 同上 |
| `guppy_red_rigged`（我的，错） | −1.63 → +1.72 | 以体中心为原点 |

**根因**：`rig_fish.py` 的烘焙是 `(x, y, z) → (x, −z, y)`。要把「背朝 +Z」变成「背朝 +Y」，这个公式实际得到的是 **−Y**——也就是翻倒了。

那为什么 AI 模型没事？因为它们的约定本来就是「**背朝 −Z**」（烘焙前肚皮朝上），烘完正好翻正。而我按「背朝 +Z」正常建模，一烘焙就颠倒：鱼眼跑到头下侧、背鳍朝下。

### 13.3 修法：不动烘焙公式，改走 Y-up 直出

改烘焙公式会影响全部已接入的 AI 模型，风险太大。改成**程序化模型走另一条路**：

1. Blender 导出时 `export_yup=True`，让导出器直接把 Z-up 转成 Y-up（背朝 +Y），烘焙就不需要了。
2. 导出前把腹部平移到 `z = 0`，这样导出后 `y ≥ 0`，与 AI 模型的包围盒约定一致（否则原点在体中心，摆位和旋转中心会和别的鱼不一致）。
3. `rig_fish.py` 增加第 5 个参数 `nobake`，跳过烘焙；`ingest.py` 增加 `--yup` 透传。

**默认行为完全不变**：AI 模型仍走烘焙，程序化模型走 `--yup`。

验证结果：

```
guppy_rigged.glb       min [-0.55, -0.0, -0.14]  max [0.64, 0.63, 0.13]
betta_rigged.glb       min [-0.62, -0.0, -0.14]  max [0.57, 0.84, 0.14]
guppy_red_rigged.glb   min [-3.53,  0.0, -0.33]  max [1.63, 3.36, 0.33]
```

三者形式一致，实机确认背朝上、尾鳍上下张开、眼睛回到头部中上。

### 13.4 按参考模型调形态

| 项 | 参考模型 | 改前 | 改后 |
| --- | --- | --- | --- |
| 体高系数 HS | 高/长 ≈ 0.35 | 0.64 | **0.70** |
| 体厚系数 WS | 厚/高 ≈ 0.43 | 0.46 | **0.50** |
| 尾鳍张角 PHI | 接近半圆 | 0.92（尖角三角） | **1.10** |
| 上颌前伸 | 钝唇 | 0.030（像短喙） | **0.015** |
| 眼睛位置 EYE_T | 头部中上 | 0.094 | **0.106** |

尾鳍边缘的正弦波动也一并减弱（0.050/0.026/0.012 → 0.030/0.015/0.008），参考模型的扇缘是圆润弧线，不是锯齿轮廓。
