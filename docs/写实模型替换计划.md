## 二、硬约束（决定排期）

### 1. 额度

`hy-3d` 是**维度级当日提交次数 5/5**，`--model 3.0` 不能绕过；`GENERATION_FAILED` 也占一次提交。

- 20 次成功任务 → 至少 **4 个额度日**；按历史 ~20% 失败率，排 **5 天窗口**（D1–D4 各 5 次，D5 全留给重试与回归）。
- 每天先提交 1 个任务探测额度：若返回 `daily submit limit exceeded (5/5)`，当日改为「只做本地收尾」（接入前一天产物、跑门禁、更新文档），不空耗。
- **串行提交，不并发**：历史上出现过按频率限制的 `429`（重置时间曾为 `2026-11-15 15:56 UTC+8`）。

### 2. 生成参数（与历史写实模型保持一致）

```bash
GEN="D:/Programs/WorkBuddy/resources/app.asar.unpacked/resources/plugins/workbuddy-builtin/skills/buddy-multimodal-generation/scripts/buddy-multimodal-generation.py"

# 前置：调用 connect_cloud_service 取 clientTempToken（ck_t_...），每次会话重新取
python3 "$GEN" 3d "<提示词>" \
  --model 3.1 --enable-pbr --face-count 45000 \
  --token "<ck_t_...>" > models/_raw/<name>.log 2>&1
```

- `--face-count 45000`：历史成功模型约 26k 顶点 / 45k 面，压缩后约 2.2 MB；脚本默认 500000 会让贴图与内嵌包暴涨。
- `--enable-pbr`：写实贴图必需。
- 检查状态：`python3 "$GEN" status <job_id> --type 3d --token "<ck_t_...>"`。
- 备用通道 `tools/gen_hunyuan.py`（直连腾讯云 `ai3d`）本机无凭证（`.ai3d_key` / `.hy3d_key` 与环境变量均不存在），**不作为计划依赖**；它的 `PROMPTS` 只作提示词模板来源。

### 3. 提示词模板（`tools/gen_hunyuan.py:39` 的硬约束）

```
写实<中文名>（<拉丁名/英文名>），单条，体长约<N>厘米，<体型/花纹/鳍特征>，
身体平直对称，所有鱼鳍完全展开，嘴唇闭合，纯色背景，
单独一条鱼，无水面、无水草、无底砂、无底座
```

> **「身体平直对称、所有鱼鳍完全展开」必须写死**，否则 `rig_fish.py` 自动绑骨会算歪脊线、拆不开鳍骨权重。水草版把「无底座 / 无底砂 / 无花盆」写进提示词，减少后续 `trim_decor_base.py` 的活。
>
> `discus` 上次报「输入图片生成几何失败，请更换图片或重试」：重试时改用**更短提示词、纯文生 3D、不传参考图**，避开几何阶段失败。

### 4. 标准接入链路

```bash
# ① 下载原始件 + 预览图
python3 tools/_fetch_raw.py <name> models/_raw/<name>.log

# ② 鱼（压贴图 → 检测头朝 -X 转 180° → 绑 12 骨 → Turn 片段 → 蒙皮闸门 → 挂 species.js → 重建内嵌包）
python3 tools/ingest.py models/_raw/<name>.glb <sid>

# ②' 水草（静态摆件，不绑骨）
python3 tools/ingest_decor.py models/_raw/<name>.glb <sid>
python3 tools/trim_decor_base.py models/<name>.glb models/_tmp/<name>_trim.glb 0.10   # 有砂盘底座才做

# ③ 每批收尾（ingest 内部已重建内嵌包，这几步仍要手动）
python3 tools/make_thumbs.py          # 重画 40 张静态图标
# 升 index.html 的 ?v=（当前 20261116b → c → d → e → f）
node tools/verify_assets.js
```

**每替换一个鱼种，立刻把它的 id 加进 `tools/gen-fish-models.js:696` 的 `AI_REPLACED`**，否则下次重跑生成器会覆盖写实资产。注意用**生成器内部 id**：`species.js` 的 `oto` 在生成器里叫 `otocinclus`（输出 `otocinclus_rigged.glb`），其余同名。当前 Set 已含 12 个：`neon, goldfish, discus, betta, cardinal, koi, clownloach, otocinclus, whitecloud, tigerbarb, swordtail, denison`。

## 四、单批标准作业流程（每批 5 个，固定顺序）

1. **备份**：`cp` 本批将被覆盖的 `models/*_rigged.glb` 或 `models/*.glb` 到 `models/_bak/<批次>/`，保留 `species.js` 副本。
2. **提交**：串行 5 次生成，日志写 `models/_raw/<name>.log`；任一 `GENERATION_FAILED` / `429` 记入重试队列，顺延到 D5，不占本批后续名额硬等。
3. **下载 + 预检**：`_fetch_raw.py` → `diagnose_glb.py` 看 accessor / NaN / bbox / 贴图 / skin / animation。
4. **接入**：鱼走 `ingest.py`，水草走 `ingest_decor.py`；逐个确认 `species.js` 只出现一条 `model:`（`patch_species()` 已修，但仍复核）。
5. **同步 `AI_REPLACED`**：把本批鱼种 id 加进 `gen-fish-models.js`。
6. **重建**：`make_thumbs.py` → 升 `index.html` 版本号 → `verify_assets.js` 六节全绿。
7. **实机点验**：Edge 打开 `http://127.0.0.1:8899/?v=<新版本>`，图鉴逐个点开本批品种，看颜色、朝向（头朝右）、鳍是否展开、旋转是否失真、`Swim` 是否在动；缸里放一条确认 `PXCM` 比例正常。
8. **记录**：工作手册追加本批结果，更新 `资产盘点-3D模型来源.md` 的写实/参数化计数。

## 五、验收门禁（每批必过）

```bash
node --check js/species.js && node --check js/render.js && node --check js/app.js

```

单项验收标准：

| 检查 | 通过条件 |
| --- | --- |
| 体积 | 鱼 1.5–4 MB（压缩后）、水草 1–3 MB；明显偏离查 `pack_model.py` |
| 朝向 | 头朝右；`rig_fish.py` 会自动检测头朝 -X 并转 180° |
| 骨骼 | 12 骨，`Swim` + `Turn`，`check_skin.py` 判据 v2 通过（塌缩 <0.65 / 爆炸 >2.2 / 增量 >0.22×最长轴 均为异常；薄体侧扁鱼不再被相对比例误杀） |
| 法线 | 零法线 0 个；写实模型历史正常，但门禁兜底 |
| 水草轴向 | Z-up 模型在 `species.js` 补 `axis: 'z'`，`make_thumbs.py` 的 `VIEW_OF` 补 `QR_AXIS=z` |
| 水草底座 | 无白色砂盘；有则 `trim_decor_base.py` 从几何删除（不能靠 `baseCut` 下沉） |
| 浮萍 | `floating` 判断 + `QR_VIEW=top`，否则按高度归一化会放大几十倍 |
| 缓存 | GLB / 图标 URL 带 `?v=AW_MODEL_VER`，页面 `?v=` 已升，浏览器不吃旧资源 |

## 六、额度优化备选（用户已否决，仅作历史记录）

> **用户已确认 D3 走全量独立生成，本节方案不启用。** 下面记录的两个前置缺陷在 D2 前已全部修复（`glbLookOf()` 支持 `breedGroup` 回退 + `soft` 低权重、`applyGlbLook()` 按 soft 用 0.45、`iconURL()` / `make_thumbs.py` 派生染色图标），保留文字是为了说明当初为什么不建议共用。

D3 的 4 个色型品种（`gold_black` / `koi_sanke` / `guppy_red` / `guppy_blue`）可以**不生成**，改为共用已写实基础模型（`goldfish` / `koi` / `guppy`）+ shader 重映射，省 4 次提交 → 总 16 次、3–4 天。

**但不能直接这么做，有两个前置缺陷：**

1. `render.js:975` 的 `glbLookOf(sp)` 开头是 `if (!sp.variantOf || !sp.look) return null;` —— **只认 `variantOf` 变体**。这 4 个品种是 `breedGroup`（独立商品），运行时核实 `variantOf` 全为「无」，共用后不会染色，会和基础品种长得一模一样。
   - 顺带发现一个**现存 bug**：`betta_red` / `betta_white` 本来就共用 `betta_rigged.glb`，且不是 `variantOf`，所以它们现在和暹罗斗鱼外观完全相同。建议把 `glbLookOf()` 的回退改成 `sp.variantOf || sp.breedGroup` 一并修掉（零额度、本地改动）。
2. `applyGlbLook()` 以 **0.88 权重**把最终 `gl_FragColor.rgb` 替换成双色（`render.js:1008`），对写实 PBR 贴图等于压掉鳞片/渐变细节。若走共用，色型品种会失去写实质感；可改成低权重色相偏移，但要多一轮 shader 调试与实机验证。

**推荐默认走全量独立生成（D1–D4）**：多 4 次提交，换来 22 个品种各自完整写实外观，且不用动 shader。§六 仅在额度紧张时启用。
