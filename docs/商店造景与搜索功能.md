# 造景商店、拼音搜索与随机造景件

对应诉求：

1. 把「沉木」「青龙石」从设备里独立出来，成为商店的「造景」tab；商店每个 tab 都带搜索框。
2. 图鉴也带搜索框。
3. 搜索支持中文名 / 英文名 / 拉丁名 / 拼音全拼 / 拼音首字母；添加沉木、青龙石时可重复添加，每次按当前缸尺寸随机生成不同大小和形状，且不越出缸体范围。

页面资源版本：`?v=20261116h`。本轮不改动任何 GLB，内嵌模型包仍是 39 个 / 83.1 MB base64。

---

## 一、商店拆出「造景」tab

`js/species.js` 保留原 `gear` 数组（兼容 `D.get('driftwood')` 和旧 `buyGear` 链路），给沉木、青龙石加 `decor: true` 与 `en` 字段，再导出 `decor` 子集：

```js
{ id: 'driftwood', kind: 'gear', decor: true, name: '沉木',
  en: 'Driftwood', price: 36, tag: '造景',
  desc: '莫斯的附着基座，也是鼠鱼和虾的躲藏处；每次添加的大小与枝形都不同。' }
{ id: 'rocks', ..., decor: true, name: '青龙石', en: 'Seiryu Stone', price: 28 }
const decor = gear.filter(g => !!g.decor);
```

`js/app.js` 的 `TABS.gear` 过滤掉 `decor`，新增 `TABS.decor = D.decor`；`index.html` 的 `shopTabs` 增加第五个按钮，并在 tabs 与列表之间插入 `shopSearch` 输入框。顶栏快捷设备条 `renderGearBar()` 在沉木前加了一条「造景」分隔标签，原来那个「沉木 +」按钮保留，点它同样走 `addDecor()` 并触发 `R.rebuild()`。

实机确认：造景 tab 只有沉木（36 币）/ 青龙石（28 币）两项；设备 tab 只剩生化过滤器、恒温加热棒、全光谱水草灯、静音气泵四件。

## 二、零依赖拼音检索

新增 `js/pinyin.js`：静态汉字 → 无声调拼音字典（`ü` 写 `v`），覆盖 `species.js` 全部 106 个 `name` 字段用到的 166 个汉字，并补齐标签、描述、色型/鳍型变体常用字。构造三种索引：

| 索引 | 含义 | 例：`红绿灯` |
| --- | --- | --- |
| `raw` | 归一化原文（含中文 / 英文 / 拉丁名） | `红绿灯`、`Paracheirodon innesi` |
| `py` | 全拼串 | `honglvdeng` |
| `ab` | 首字母串 | `hld` |

`match(idx, q)` 对三者做子串匹配，导出 `window.AW_PY`。不引入 `pypinyin`、不引入前端大字典、不需要构建步骤，`file://` 与 `http://` 都能跑。

`js/app.js` 的 `searchOf(sp)` 把 `name / latin / en / id / tags / tag / desc` 拼成索引并缓存；`filterList(list, q)` 作用于**当前 tab**，`dexQuery` 同理作用于**当前图鉴分类**。切换 tab 时保留关键词，方便跨类目比对。`emptyHint()` 在无结果时提示可试中文名、英文名、全拼（chenmu）或首字母（cm）。

**已知行为（不是缺陷）**：索引包含描述文本，所以搜 `hld` 会同时带出「宝莲灯」——它的描述写着「比**红绿灯**更艳的灯科鱼」。量化检查：10 组随机 3 字母在 67 条描述里命中 0/67，长描述不会让首字母检索退化成「什么都命中」。中文/英文子串命中描述属于正常的全文联想。

## 三、可重复添加的随机造景件

### 数据层（`js/sim.js`）

存档新增 `decorItems: { wood: [], rock: [] }`，每件是独立实例 `{ x, z, s, seed, shape, cm }`：

```js
function randomDecor(s, kind) {
  var t = D.tank(s.tankSize);
  var sc = rnd(.62, 1.28);                 // 大小随机
  var it = {
    x: rnd(.10, .90), z: rnd(.16, .84),   // 位置避开缸壁
    s: sc, seed: Math.floor(rnd(1, 1e9)),
    shape: kind === 'wood' ? Math.floor(rnd(0, 4))
      : ['pebble', 'angular', 'slate'][Math.floor(rnd(0, 3))]
  };
  var unitCm = t.cm / t.w;                 // 1 个 3D 单位 = 多少真实厘米
  it.cm = Math.round((kind === 'wood' ? t.h * .26 : t.d * .12) * sc * unitCm * 10) / 10;
  return it;
}
```

- `s` 是**相对系数**，渲染层再乘当前 `TANK` 尺寸，因此换缸后同一件等比缩放，高度不会戳出水面、石径不会穿出缸壁。
- `cm` 用 `t.cm / t.w` 换算成真实厘米，商店显示的数字与缸里看到的大小一致。
- `DECOR_MAX = 12`，同类最多 12 件；`buyGear()` 遇到 `g.decor` 重定向到 `addDecor()`，可反复购买；`addDecor()` 返回 `rebuild: true`，UI 据此调用 `R.rebuild(state)` 让新几何立刻出现。
- `setDecorPos()` 把拖拽落点夹在 `[.06,.94] × [.10,.90]`，供布景摆位模式使用。
- `sanitize()` 补出旧存档缺失的 `decorItems`、剔除损坏 / NaN 实例、裁剪到上限。

### 渲染层（`js/render.js`）

- 新增 `makeWoodPiece(...)`：`shape`（0–3）决定主干倾斜、弯曲与分叉数量，`seed` 通过 `hash()` 扰动，用 `CatmullRomCurve3` + `TubeGeometry` 生成互不相同的枝形。
- 青龙石复用 `buildGlbRock(it.shape, ...)`，三种石形 `pebble / angular / slate` 各有不同 GLB。
- `buildStatic()` 在原有设置面板石头组之外，逐件读 `decorItems.rock / .wood` 生成实例；每件挂 `decorKind / decorIdx / rockLift`。
- `pickLayout()` 返回 `kind: 'decor'`，`movePlace()` 与 `pointerup` 定稿分支走 `handlers.layoutDecor()` → `SIM.setDecorPos()`。

### UI（`js/app.js`）

造景卡片显示「已摆 N/12 件」、随机造型说明与「最近一件约 X cm」；按钮从「添加一件」变成「再添一件」。

## 四、门禁

| 脚本 | 检查内容 |
| --- | --- |
| `tools/verify_pinyin.js` | `species.js` 全部名称汉字覆盖率；中文 / 英文 / 拉丁名 / 全拼 / 首字母 / 负例 / 空关键词 |
| `tools/verify_decor.js` | 四档缸各 12 件字段合法且不越界、`cm` 与渲染尺寸换算一致、确定性基准尺寸随缸增大、连续 8 根沉木尺寸与枝形随机、8 块青龙石石形随机、12 件上限、拖拽夹取、存档回读、旧存档迁移、损坏数据清理 |
| `tools/verify_assets.js` | 原【1】–【6】之外，新增【7】拼音检索、【8】造景实例；两者以**子进程**调用，避免子脚本各自覆盖 `global.window` / `localStorage` 污染主门禁数据源 |

**修掉的 flaky 门禁**：初版用「每档 12 件随机样本的 `cm` 中位数」验证「件尺寸随缸增大」，但随机系数 `s ∈ [.62,1.28]` 波动达 2.06 倍，远大于相邻缸 1.19–1.37 倍的尺寸差，12 次连跑有 3 次误报（45cm→5.5cm 而 60cm→5.2cm）。改为在**固定随机源**（`Math.random = () => .5`）下只验证「缸尺寸」这一条因果，随机性交给另外两项专门检查；同时新增 `cm` 必须等于 `(渲染尺寸 × s × t.cm/t.w)` 的校验（允许 0.06cm 四舍五入误差）。修完 30 次连跑零失败。这是测试设计缺陷，产品逻辑本身一直是对的。

## 五、验证结果

- `node tools/verify_assets.js`：**【1】–【8】全部通过**（含 39 个 GLB 无零法线）。
- `node tools/verify_decor.js` 30 次连跑：0 失败。
- 全部 `js/*.js`、`tools/*.js` 通过 `node --check`。
- 本地服务 `http://127.0.0.1:8899/` 返回 200。
- **Edge 实机点验**：
  - 造景 tab 拆分正确、设备 tab 仅 4 件设备。
  - 商店搜 `cm` → 只剩沉木；`qls` → 只剩青龙石；`seiryu` → 青龙石；无结果时给出中文/全拼/首字母提示。
  - 图鉴搜 `hld` → 红绿灯（及描述含红绿灯的宝莲灯）；`poecilia` → 孔雀鱼系列 4 项；空结果提示正常；3D 展示台孔雀鱼模型颜色正常。
  - 连续添加沉木 4 件、青龙石 3 件：商店计数 `4/12`、`3/12`，尺寸提示从 `9.9 cm` 变到 `10.3 cm`（石头 `3 cm`），按钮变「再添一件」；缸内可见多根高度/分叉不同的沉木枝与多块大小不同的青龙石，均在缸体范围内。
  - 切到「布景摆位」拖拽一根沉木后，实例未丢失、计数仍为 `4/12`，落点被夹在缸内。

## 六、边界与后续

- 同类造景最多 12 件，超出会提示「缸里放不下了」；两类合计最多 24 件。
- 造景件没有独立删除入口，只能在「重置水族箱」时清空；如需单件移除，后续可加一个回收按钮（按 `decorIdx` 从数组移除并 `R.rebuild()`）。
- 写实模型替换计划 D3–D4 共 10 次生成仍待下一额度日，与本轮改动互不冲突。
