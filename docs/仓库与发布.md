# 仓库与发布

这份文档记录「什么进版本库、什么不进、怎么发出去」，以及本机网络的坑。改结构或换发布方式时同步更新。

## 一、仓库现状

| 项 | 值 |
| --- | --- |
| 远程 | https://github.com/ddanmark/aquarium.git |
| 主分支 | `main`（首次入库前已有 `Initial commit`：LICENSE + 占位 README） |
| 许可 | MIT © 2026 Nasblance |
| 首个项目提交 | `chore: 项目入库（首次提交）`，128 个文件 / 约 61MB 打包体积 |

## 二、结构约定

```
index.html  style.css       页面与样式（无构建步骤，直接生效）
js/                         运行时代码：species → sim → render → app
models/*.glb                写实模型（入库）
models/thumbs/*.png         列表缩略图（入库，前端只 drawImage）
vendor/                     three.js r149 + GLTFLoader + SkeletonUtils（入库，便于离线）
tools/                      资产流水线与门禁脚本（入库）
docs/                       设计与迭代文档（入库）
```

新增运行时文件时放在 `js/`；新增脚本放 `tools/`；新增说明文档放 `docs/`。根目录只保留入口文件、README 和工程配置。

## 三、不入库的文件

| 路径 | 体积 | 为什么不入库 | 怎么再生成 |
| --- | --- | --- | --- |
| `models/_raw/` | ~1.2G | AI 生成的原始 GLB、预览渲染图与日志 | 用 `tools/gen_hunyuan.py` 重新拉取 |
| `models/_tmp/` | ~108M | 压贴图 / 绑骨 / 打包的半成品 | `tools/pack_model.py` → `rig_fish.py` 串一遍 |
| `models/_test/` | ~9M | 诊断用对比图、contact sheet | 无（一次性排查产物） |
| `models/_bak/` | ~3M | 历史备份与被清理的孤儿件 | 无 |
| `js/models/` | ~98M | `models/*.glb` 的 base64 内嵌包，纯生成物 | `npm run build:models` |
| `models/compare-new-fish.html` | 19K | 开发期模型对比页，依赖 `_raw` 原图 | 无 |
| `.workbuddy/` | — | 本地会话记忆 | 无 |

`js/models.js`（清单与缓存版本号）**入库**：它是内嵌包的索引，前端按 `AW_MODEL_VER` 做 `?v=` 缓存击穿。
只缺 `js/models/*.js` 时页面仍可用，走路由 `render.js` 的三级加载决定：

1. `http(s)` → 直接取 `models/<名字>.glb?v=…`
2. `file://` 或 URL 失败 → 注入 `js/models/<名字>.js` 解码 base64
3. 都失败 → 回退程序化几何

所以「线上跑」和「双击 index.html 跑」对资产的要求不同，前者只需要 `models/*.glb` 入库。

## 四、常用命令

```bash
npm run serve          # 本地静态服务 http://localhost:8080
npm run verify         # 资源一致性门禁（10 组检查）
npm run build:models   # 重建 js/models 内嵌包（需要 file:// 直开时才跑）
```

提交前跑一次 `npm run verify`，全绿再提交。

## 五、发布到 GitHub Pages

1. 仓库 Settings → Pages → Source 选 `Deploy from a branch`，分支 `main`、目录 `/ (root)`
2. 访问 `https://ddanmark.github.io/aquarium/`

页面是纯静态的，`models/*.glb` 按 URL 加载，Pages 默认就返回 `model/gltf-binary` 可用的响应，无需额外配置。
若之后加了自定义域名或子路径部署，注意 `render.js` 里 `models/` 与 `js/models/` 都是相对路径，无需改动。

## 六、本机网络备注（重要）

本机 `github.com` 的 DNS 被解析到 `20.247.166.64`，该地址不可达（`curl` 报 `Connection was reset`），
但真实 IP `140.82.113.4` 可正常握手，`api.github.com` 也可直连。

绕行方式：起一个只改写 `github.com:443` 目标的本地 CONNECT 转发，让 git 走它。

```bash
node "$TEMP/gh-connect-proxy.js" 9418
git -c http.proxy=http://127.0.0.1:9418 push -u origin main
```

脚本内容见会话记录；只用 `-c` 临时指定，不写进 `.git/config` 或全局配置。凭据由 Git Credential
Manager（`PortableGit/1.3.0/mingw64/bin/git-credential-manager.exe`）保存到 Windows 凭据管理器，
账号 `ddanmark`，后续推送不再需要输入。

> 全局 `credential.helper` 指向的 `~/.workbuddy-ai/.../1.2.0/...` 是失效路径，实际可用的是 `~/.workbuddy/.../1.3.0/...`。
